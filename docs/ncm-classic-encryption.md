# 经典 NCM 容器与加密流程

NCM 将音频、歌曲信息和封面封装在同一文件中。其中，音频流密钥和歌曲信息分别经过 AES 加密，音频数据通过密钥流异或处理，封面保存为原始图片数据

本文说明 NCM Breaker 支持的经典 NCM 结构及各数据区的加密过程。读取和恢复文件的步骤见[经典 NCM 解密流程](ncm-classic-decryption.md)

## 容器结构

文件中的字段按下表顺序排列。长度字段均为 4 字节无符号整数，采用小端序，即低位字节在前

| 字段 | 长度 | 内容 |
| --- | --- | --- |
| 固定标识 | 8 字节 | ASCII 文本 `CTENFDAM` |
| 格式标记 | 2 字节 | 例如 `01 70`，作为格式特征读取 |
| 密钥区长度 | 4 字节 | 加密密钥区的字节数 |
| 密钥区 | 由前一字段指定 | 封装后的音频流密钥 |
| 元数据区长度 | 4 字节 | 加密元数据区的字节数 |
| 元数据区 | 由前一字段指定 | 封装后的歌曲信息 |
| CRC 字段 | 4 字节 | 校验字段 |
| 保留区域 | 5 字节 | 保留数据 |
| 封面长度 | 4 字节 | 图片数据的字节数 |
| 封面区 | 由前一字段指定 | 原始图片数据 |
| 音频区 | 至文件结尾 | 加密后的音频数据 |

格式识别结合固定标识、字段边界和解码结果进行。两字节格式标记的具体含义尚未确定；NCM Breaker 读取该标记，并跳过 CRC 字段和保留区域

## 封装音频流密钥

音频流密钥是一段非空字节序列，用于生成音频加密所需的置换表。封装时，先在密钥前添加 17 字节 ASCII 前缀 `neteasecloudmusic`，再使用 AES-128-ECB 加密

AES 固定密钥为以下 16 个 ASCII 字节：

```text
hzHRAmso5kInbaxW
```

填充采用 PKCS#7 规则，按 AES 的 16 字节分组补齐；Java 中对应的变换名称为 `AES/ECB/PKCS5Padding`

AES 加密后，将每个密文字节与 `0x64` 异或，得到文件中的密钥区。密钥区前的长度字段记录最终结果的字节数

```text
"neteasecloudmusic" + 音频流密钥
    -> AES-128-ECB 加密并使用上述填充
    -> 每字节 XOR 0x64
    -> 密钥区
```

## 封装歌曲信息

歌曲信息以 UTF-8 JSON 表示，可包含歌曲 ID、歌曲名、歌手、专辑、码率、时长和音频格式等字段，具体内容取决于文件

先在 JSON 前添加 6 字节 ASCII 前缀 `music:`，再使用 AES-128-ECB 加密，填充方式与密钥区相同。此处使用另一组固定密钥：

```text
#14ljk_!\]&0U<'(
```

上述文本按 ASCII 字节使用，其中反斜杠占一个字节

将 AES 密文进行 Base64 编码，在编码结果前添加 22 字节 ASCII 前缀 `163 key(Don't modify):`，最后将整个字节序列与 `0x63` 逐字节异或，得到元数据区

```text
"music:" + UTF-8 JSON
    -> AES-128-ECB 加密并使用上述填充
    -> Base64 编码
    -> 添加 "163 key(Don't modify):" 前缀
    -> 每字节 XOR 0x63
    -> 元数据区
```

## 生成音频密钥流

音频加密采用基于 RC4 密钥调度的变体。先用音频流密钥生成包含 0 到 255 的置换表 `S`，再从该表计算密钥流字节

以下计算将 `key` 中的每个字节视为 0 到 255 的无符号整数，`keyLength` 为密钥长度，`%` 表示取余

```text
for i = 0 .. 255:
    S[i] = i

j = 0
for i = 0 .. 255:
    j = (j + S[i] + key[i % keyLength]) % 256
    交换 S[i] 和 S[j]
```

置换完成后，`S` 保持不变。令 `p` 为相对于音频区起点的字节偏移，从 0 开始计数，则对应的密钥流字节为：

```text
i = (p + 1) % 256
j = (S[i] + i) % 256
K[p] = S[(S[i] + S[j]) % 256]
```

与标准 RC4 在生成密钥流时持续更新置换表的方式相比，此处使用固定的 `S`，密钥流按 256 字节重复

## 加密音频与保存封面

将原始音频的每个字节与对应密钥流字节异或，得到音频区内容：

```text
密文[p] = 明文[p] XOR K[p]
```

该过程保留原始音频编码，MP3 和 FLAC 数据在恢复后仍采用各自原有的编码。由于异或操作可逆，加密和解密使用相同的密钥流

封面区直接保存图片字节，NCM Breaker 支持识别其中的 JPEG 和 PNG 图片。封面长度为 0 时，音频区紧接在封面长度字段之后
