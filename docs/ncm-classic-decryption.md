# 经典 NCM 解密流程

经典 NCM 的解密过程依次恢复音频流密钥、歌曲信息和音频数据，并读取容器中的封面。本文按文件读取顺序介绍各步骤，字段布局与加密原理见[经典 NCM 容器与加密流程](ncm-classic-encryption.md)

## 读取文件头

读取文件开头的 10 字节：前 8 字节为 ASCII 固定标识 `CTENFDAM`，后 2 字节为格式标记，例如 `01 70`

后续长度字段均按 4 字节无符号小端整数读取。读取每个数据区前，先确认其长度字段完整，且声明的长度处于文件剩余范围内

## 恢复音频流密钥

1. 读取密钥区长度及对应的完整数据区
2. 将每个字节与 `0x64` 异或，得到 AES 密文
3. 使用下列固定密钥执行 AES-128-ECB 解密，并移除填充
4. 验证明文的前 17 字节为 `neteasecloudmusic`
5. 移除前缀，取剩余的非空字节序列作为音频流密钥

AES 固定密钥为以下 16 个 ASCII 字节：

```text
hzHRAmso5kInbaxW
```

填充按 AES 的 16 字节分组采用 PKCS#7 规则，Java 中对应的变换名称为 `AES/ECB/PKCS5Padding`

## 恢复歌曲信息

1. 读取元数据区长度及对应的完整数据区
2. 将每个字节与 `0x63` 异或
3. 验证并移除 22 字节 ASCII 前缀 `163 key(Don't modify):`
4. 对剩余内容执行 Base64 解码，得到 AES 密文
5. 使用下列固定密钥执行 AES-128-ECB 解密，并按相同规则移除填充
6. 验证并移除 6 字节 ASCII 前缀 `music:`
7. 将剩余内容按 UTF-8 解码，并解析为 JSON 对象

元数据 AES 固定密钥为：

```text
#14ljk_!\]&0U<'(
```

上述文本按 ASCII 字节使用，其中反斜杠占一个字节。JSON 中的 `musicName`、`artist`、`album` 和 `format` 等字段分别描述歌曲名、歌手、专辑和声明的音频格式

## 读取封面并定位音频区

元数据区之后依次是 4 字节 CRC 字段、5 字节保留区域和 4 字节封面长度。NCM Breaker 跳过前两项，读取封面长度，再读取对应的原始图片数据

常见图片文件头如下：

| 图片类型 | 文件头的十六进制字节 |
| --- | --- |
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47 0D 0A 1A 0A` |

封面区结束的位置就是音频区起点，音频区延伸至文件结尾。封面长度为 0 时，音频数据紧接在封面长度字段之后

## 恢复音频数据

先根据音频流密钥初始化置换表 `S`。以下计算将密钥字节视为 0 到 255 的无符号整数，`keyLength` 为密钥长度

```text
for i = 0 .. 255:
    S[i] = i

j = 0
for i = 0 .. 255:
    j = (j + S[i] + key[i % keyLength]) % 256
    交换 S[i] 和 S[j]
```

令 `p` 为相对于音频区起点的字节偏移，从 0 开始计数。对每个密文字节计算：

```text
i = (p + 1) % 256
j = (S[i] + i) % 256
K[p] = S[(S[i] + S[j]) % 256]
明文[p] = 密文[p] XOR K[p]
```

此阶段的置换表保持不变，密钥流按 256 字节重复。分块读取时，使用 `p = 已处理的音频字节数 + 块内偏移`，即可让任意大小的缓冲区衔接到同一条密钥流

## 识别音频格式

NCM Breaker 根据恢复后的音频头选择输出格式：

| 音频头特征 | 识别结果 |
| --- | --- |
| `49 44 33`，即 ASCII 文本 `ID3` | 按带 ID3 标签的 MP3 处理 |
| `66 4C 61 43`，即 ASCII 文本 `fLaC` | FLAC |
| 首字节为 `FF`，次字节高 3 位为 `111` | 按 MP3 帧同步特征处理 |

这些特征用于初步识别格式，音频内容的完整有效性仍需由音频解码器判断。识别成功后，分别采用 `.mp3` 或 `.flac` 扩展名保存

## 写入歌曲信息与封面

恢复后的音频保留原有编码。对于 MP3，还可以将容器中的歌曲信息和封面写入 ID3v2 标签：

| 内容 | ID3v2 帧 |
| --- | --- |
| 歌曲名 | `TIT2` |
| 歌手 | `TPE1` |
| 专辑 | `TALB` |
| 封面图片 | `APIC` |

NCM Breaker 的图形界面提供歌曲信息和封面写入选项，命令行模式恢复原始音频。FLAC 输出保留音频中已有的元数据

## 解析结果

NCM Breaker 用以下状态报告容器解析结果：

| 状态 | 含义 |
| --- | --- |
| `CLASSIC_NCM` | 经典容器、密钥和元数据可解析；音频被识别为 MP3 或 FLAC 时可转换 |
| `NOT_NCM` | 固定标识与 `CTENFDAM` 不匹配 |
| `DAMAGED` | 文件读取失败、字段长度越界、数据截断或音频区为空 |
| `UNSUPPORTED_VARIANT` | 固定标识匹配，但经典密钥或元数据解码失败 |

其中，`UNSUPPORTED_VARIANT` 表示当前解析方法无法解码该文件，具体原因可能是格式差异或数据损坏
